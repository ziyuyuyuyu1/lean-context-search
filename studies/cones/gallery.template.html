Study notes

Two kinds of relations

Parent interfaces

A structure supplies a parent through a Lean projection. Example: AddAction → VAdd.

Property implications

One property implies another for the same object or map. Example: IsIso f → Mono f.

Generalization failure

0 / 6

No hyperbolic run passed the transfer check

Two architectures × three seeds, tested on 12 development pairs across two groups. Synthetic transfer was also unstable across seeds.

Possible reasons

A learned vector summarizes a declaration. The relation we want is stricter: can its fields and laws actually supply another interface, with the right types and parameters?

Traversable t→Functor t

This arrow needs a valid toFunctor map and the same t on both sides. The hyperbolic model missed it in a saved development example.

Details can disappear

Language embeddings summarize descriptions; the structural features summarize fields and types. Either summary can lose distinctions that matter to the Lean map.

A fit can learn positions

Training can arrange familiar interfaces into the right cones without learning a rule that places a new interface correctly.

Geometry does not check types

The cone tests position and angle. It does not construct a projection or verify its parameter substitutions.

These are possible explanations; the cause is not yet isolated. Some tested feature encodings gave distinct interfaces identical inputs.

No retrieval gain

The hyperbolic branch did not improve the mean score. This development study is separate from the release’s public benchmark.
